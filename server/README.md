# FluteBand AI — OMR-сервис (распознавание нот)

Превращает фото страницы в **MusicXML**, из которого приложение строит минус.

## Два способа запустить

### 1. Заглушка (без установок, только Python)

```bash
python server/standalone.py          # http://127.0.0.1:8000
```

Отдаёт эталонный MusicXML. Нужна, чтобы проверить весь тракт «страница → музыкальная модель → минус»
до подключения настоящего распознавания.

### 2. Боевой сервис (FastAPI + OMR-движок)

```bash
# зависимости кладём в server/deps (venv в этой среде недоступен)
pip install --target server/deps -r server/requirements.txt
pip install --target server/deps homr            # основной движок распознавания (ONNX, CPU)

# запуск (PYTHONPATH обязателен, если зависимости в server/deps)
set PYTHONPATH=server/deps && python -m uvicorn main:app --app-dir server --host 127.0.0.1 --port 8000
# или из корня проекта: npm run omr:real
```

Проверить, что движок виден сервису:

```bash
curl http://127.0.0.1:8000/engines
```

Проверить распознавание настоящей страницы (демо-страница лежит в приложении):

```bash
python server/tools/recognize.py app/demo/ode-page.png --engine=homr --out=page.musicxml
node tools/omr-check.mjs http://127.0.0.1:8000 app/demo/ode-page.png
```

Модели homr (~82 МБ) скачиваются при первом запуске; каталог кэша задаётся `HF_HOME`
(по умолчанию `.omr-work/cache`).

### 3. Контейнер / бесплатный облачный тариф (Hugging Face Spaces и аналоги)

Пакет для загрузки в Space собирается одной командой из корня проекта (сервер + `Dockerfile` + `README.md`
с шапкой Spaces: `sdk: docker`, `app_port: 7860`):

```bash
npm run pack:space                       # → dist-space/
docker build -t fluteband-omr dist-space
docker run --rm -p 7860:7860 fluteband-omr
```

Проверить локально **как на бесплатном тарифе** (2 ядра, 4 ГБ):

```bash
docker run --rm -p 7860:7860 --cpus=2 --memory=4g fluteband-omr
node tools/omr-check.mjs http://127.0.0.1:7860 app/demo/ode-page.png
```

Что делает образ: ставит движок `homr`, скачивает его модели **на сборке** (`homr --init`, чтобы первый
запрос ученика не ждал загрузки), добавляет системные библиотеки для OpenCV (`libgl1`, `libglib2.0-0`,
`libxcb1`, `libsm6`, `libxext6` — без них распознавание падает с `ImportError: libxcb.so.1`), работает не от
root и держит рабочие каталоги в `/tmp`. Размер образа 1.87 ГБ, модели внутри — 152 МБ.

Измерено на контейнере с двумя ядрами (как на бесплатном тарифе): демо-страница — 23.4 с, плотная
страница «фортепиано + блокфлейта» — 130.2 с (дома, на 16 ядрах, 34.7 с), повтор той же страницы — 5 мс
из кэша результатов. Предел времени задаётся `RECOGNIZE_TIMEOUT` (в образе 240 с); при нехватке времени
сервис отвечает **504** с понятным текстом, а не «Internal Server Error».

Пошаговая выкладка на Spaces и чек-лист — `docs/05-publikaciya.md`.

## Контракт API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/health` | состояние, список доступных движков, лимиты |
| GET | `/engines` | какие движки установлены и под какими лицензиями |
| POST | `/recognize` | `multipart/form-data`: `image` (JPEG/PNG) + необязательный `engine` → `{musicxml, engine, confidence, warnings, elapsedMs}` |

Приложение обращается к сервису через свой префикс `/api` — dev-сервер (`tools/serve.mjs`) проксирует
`/api/*` на `OMR_URL` (по умолчанию `http://127.0.0.1:8000`). Переменные: `OMR_URL`, `OMR_URL=off` отключает прокси.

## Движки

Все движки выбираются в `server/engines.py`; сервис сам берёт первый рабочий (порядок: `homr` → `oemer` → `audiveris` → `stub`).

| id | Лицензия | Состояние |
|---|---|---|
| `stub` | — | работает всегда, отдаёт эталонный MusicXML (для проверки тракта без установок) |
| `homr` | свободная (см. репозиторий) | **основной, проверен**: ONNX-инференс на CPU, ~7 с на страницу |
| `oemer` | MIT | установлен, но с `onnxruntime` 1.30 падает: `ConvTranspose … pads must not contain negative values` — помечен «не проверен» |
| `audiveris` | AGPL | требует Java, в этой среде недоступен |

### Измеренная точность (стенд, 6 учебных пьес, homr)

| Метрика | Значение |
|---|---|
| F1 по нотам | 83.6% |
| Верная тональность | 100% |
| Верный размер | 83% |
| Верная длительность нот | 78.9% |
| Среднее время страницы | 7.0 с |

Полный отчёт — `docs/omr-benchmark.md` (обновляется `npm run bench`). Разбор типовых ошибок движка
(лишний такт на переносе строки, 6/8 ↔ 3/8, пунктирные длительности, отсутствие `<mode>` и аккордов)
описан в `docs/04-status.md`.

## Приватность и лимиты

- изображения обрабатываются в памяти и **не сохраняются**; в логах нет картинок;
- лимит размера: `MAX_IMAGE_BYTES` (по умолчанию 12 МБ), таймаут распознавания: `RECOGNIZE_TIMEOUT` (90 с);
- кэш по SHA-256 изображения (`CACHE_SIZE`, по умолчанию 32 записи) — повторное распознавание той же страницы мгновенно;
- приложение сжимает снимок до 2000 px по длинной стороне перед отправкой.

## Что делать, если сервер недоступен

В приложении предусмотрены обходные пути, и ученик всё равно получит рабочий минус:

- **загрузить файл MusicXML** (.musicxml/.xml) — он разбирается прямо в браузере, сервер не нужен;
- **демо-страница** — готовая страница нот для проверки распознавания, когда камеры под рукой нет;
- **эталонная страница** (демо-режим движка `stub`) и **ручной ввод аккордов**.

Подробности — в `docs/02-resheniya.md`.
