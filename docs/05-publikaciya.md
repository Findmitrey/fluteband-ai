# Публикация на бесплатном хостинге

Приложение FluteBand AI состоит из двух частей, и выкладываются они на разные бесплатные площадки:

| Часть | Что это | Куда | Деньги |
|---|---|---|---|
| **Приложение** | статические файлы (`dist/`, 46 файлов, 0.44 МБ) | Netlify (проще всего) **или** Cloudflare Pages **или** GitHub Pages | бесплатно, без карты |
| **Сервис распознавания** | Python + ONNX-движок `homr`, Docker | Hugging Face Spaces (Docker, Free CPU) | бесплатно, без карты |

Сервис — это Python и нейросетевой движок, на статическом хостинге он жить не может. Зато он не нужен
для игры: приложение само по себе офлайновое (ПВА, кэш оболочки), а сервис нужен только чтобы превратить
**фото нот** в нотный текст. Готовые `.musicxml` приложение разбирает на устройстве, без сервиса.

---

## 1. Собрать пакеты

```bash
npm run build:static      # → dist/       (приложение)
npm run check:static      # проверка: подкаталог, service worker, офлайн без сети (GitHub Pages)
npm run check:netlify     # проверка: приложение в корне сайта (Netlify, Cloudflare Pages)
npm run pack:space        # → dist-space/ (сервис распознавания)
```

`check:static` поднимает `dist/` в подкаталоге (как на GitHub Pages), включает Chrome и проверяет
по-настоящему: файлы оболочки отдаются, service worker встаёт с областью подкаталога, оболочка ложится
в кэш, затем **сеть выключается** и приложение всё равно открывается и строит минус. Если эта проверка
прошла — выкладка не сюрпризов не принесёт. `check:netlify` делает то же самое для корня сайта, а
`npm run check:netlify:pretty` — ещё и с включёнными «красивыми адресами» (см. ниже).

При сборке имя кэша оболочки привязывается к содержимому пакета (`fluteband-shell-<хеш>`), поэтому после
обновления ученик получает новую версию, а не старое из кэша. Руками имя менять не нужно.

## 2. Приложение: Netlify (самый простой путь)

Даёт корень сайта (`https://имя.netlify.app`), HTTPS (нужен для камеры на телефоне), сборку из
репозитория и не требует карты. Ничего доустанавливать не нужно: пакет уже собран и проверен.

### Как выложить готовую папку (без репозитория, 2 минуты)

1. Зайдите на <https://app.netlify.com/drop> и войдите (можно через GitHub, Google или почту —
   бесплатный тариф, карта не нужна).
2. Соберите пакет и перетащите в окно **содержимое** папки `dist/` (не саму папку):

   ```bash
   npm run build:static
   ```

   Внутри должны быть: `index.html`, `js/`, `css/`, `icons/`, `demo/`, `manifest.webmanifest`,
   `service-worker.js`, `_headers`, `.nojekyll`.
3. Готово: адрес будет вида `https://случайное-имя.netlify.app`. В **Site configuration → Change site
   name** можно задать своё имя → `https://fluteband.netlify.app`.
4. Обновление версии — снова `npm run build:static` и снова перетащить папку (или подключить
   репозиторий, тогда обновление идёт по `git push`).

### Как выложить из репозитория (обновления по git push)

1. Загрузите проект в GitHub (или GitLab/Bitbucket) — репозиторий может быть закрытым. Папка проекта
   **пока не является git-репозиторием**, поэтому первый раз нужно её инициализировать:

   ```bash
   git init
   git add -A
   git commit -m "FluteBand AI"
   git branch -M main
   git remote add origin https://github.com/имя/fluteband.git
   git push -u origin main
   ```

   В репозитории нет зависимостей (`package.json` без `dependencies`), а `dist/`, `dist-space/` и рабочие
   каталоги распознавания перечислены в `.gitignore` — на Netlify поедет только исходный код.
2. Netlify: **Add new project → Import an existing project** → выберите репозиторий.
3. Настройки подставятся из `netlify.toml` в корне проекта, проверьте их в форме:
   | Поле | Значение |
   |---|---|
   | Build command | `npm run build:static` |
   | Publish directory | `dist` |
   | Branch to deploy | основная ветка (`main`) |
4. **Deploy**. Сборке не нужны зависимости: `npm run build:static` — это обычный Node-скрипт без
   сторонних пакетов, поэтому она занимает секунды и не тратит минуты сборки. Версия Node закреплена в
   `netlify.toml` (`NODE_VERSION = "20"`), чтобы сборка не зависела от версии по умолчанию на площадке.

### Что уже настроено в `netlify.toml` (менять не нужно)

- **Сборка и папка публикации** — `npm run build:static` и `dist`.
- **«Красивые адреса» выключены** (`pretty_urls = false`). Это важно: иначе Netlify превращает
  `/index.html` в `/`, а приложение кэширует оболочку по конкретным адресам и стартовый адрес PWA —
  именно `./index.html`. Проверено и так и так: даже если эту настройку случайно включить, приложение
  всё равно собирает офлайн-кэш (в `dist/_headers` и в самом service worker есть страховка) —
  см. `npm run check:netlify:pretty`.
- **Заголовки**: service worker отдаётся с `Cache-Control: no-cache` (иначе обновление не доедет до
  ученика), манифест — как `application/manifest+json` (по этому типу Chrome понимает, что приложение
  можно установить). Те же заголовки лежат в `dist/_headers`, поэтому работают и при выкладке папки.
- **Прокси распознавания выключен намеренно.** У прокси-запросов Netlify есть предел **26 секунд**
  ([документация](https://docs.netlify.com/manage/routing/redirects/rewrites-proxies/)), а распознавание
  плотной страницы занимает 130 с на бесплатном тарифе сервиса. Поэтому приложение обращается к сервису
  **напрямую**: адрес вводится на экране «Сканировать» → «Адрес сервиса» (у сервиса открыт CORS).
  Проксировать имеет смысл только быстрые, разреженные страницы; готовый блок для этого лежит
  закомментированным в `netlify.toml`.

> Свой домен подключается бесплатно (**Domain management → Add a domain**), но нужен сам домен —
> бесплатного имени Netlify не выдаёт. Для установки PWA и камеры хватает и адреса `…netlify.app`.

## 3. Приложение: Cloudflare Pages (тоже просто)

Даёт корень сайта (`https://имя.pages.dev`), HTTPS (нужен для камеры на телефоне) и не требует карты.

**Через браузер, без установки программ:**

1. Зайдите на <https://dash.cloudflare.com> и создайте бесплатный аккаунт.
2. **Workers & Pages → Create → Pages → Upload assets**.
3. Имя проекта, например `fluteband` (адрес будет `https://fluteband.pages.dev`).
4. Перетащите **содержимое** папки `dist/` (не саму папку): `index.html`, `js/`, `css/`, `icons/`,
   `demo/`, `manifest.webmanifest`, `service-worker.js`, `_headers`, `.nojekyll`.
5. **Deploy**. Через несколько секунд приложение открывается по адресу вида
   `https://fluteband.pages.dev/index.html`.

**Через командную строку (то же самое, удобно повторять):**

```bash
npx wrangler pages deploy dist --project-name=fluteband
```

Обновление версии — снова `npm run build:static`, затем повторная выкладка (или `git push`, если проект
подключён к репозиторию: Cloudflare Pages собирает ветку сам, команда сборки не нужна).

## 3. Приложение: GitHub Pages (подкаталог)

Приложение проверено и для этого случая: адрес будет `https://имя.github.io/fluteband/`, то есть
приложение живёт **в подкаталоге** чужого корня. Все пути в приложении относительные, `.nojekyll` уже
в пакете.

1. Создайте **публичный** репозиторий (бесплатные Pages — только для публичных репозиториев).
2. Положите содержимое `dist/` в ветку, с которой публикуете:

```bash
git clone https://github.com/имя/fluteband.git && cd fluteband
# скопируйте сюда содержимое dist/
git add -A && git commit -m "FluteBand AI" && git push origin main
```

3. **Settings → Pages → Source: Deploy from a branch**, ветка `main`, папка `/ (root)` → **Save**.
4. Через минуту приложение открывается: `https://имя.github.io/fluteband/index.html`.

Без аккаунта GitHub тоже можно: Pages требует репозиторий, но карту — нет.

## 5. Сервис распознавания: Hugging Face Spaces

1. Аккаунт на <https://huggingface.co> (бесплатный).
2. **New Space**: имя `fluteband-omr`, **SDK: Docker**, **Hardware: CPU basic (free)** — 2 ядра, 16 ГБ.
3. Загрузите содержимое `dist-space/` в репозиторий пространства:

```bash
git clone https://huggingface.co/spaces/имя/fluteband-omr && cd fluteband-omr
# скопируйте сюда содержимое dist-space/
git add -A && git commit -m "OMR service" && git push
```

4. Space соберёт образ сам. Это долго (несколько минут): Python, FastAPI и движок `homr` с ONNX.
5. Проверьте, что сервис жив:
   `https://имя-fluteband-omr.hf.space/health` → `{"status":"ok",…}`,
   `…/engines` → в списке должен быть доступен `homr`.

**Альтернативы:** Render (бесплатный веб-сервис из Docker; засыпает после 15 минут простоя, первый запрос
после сна — до минуты), Fly.io (небольшой бесплатный лимит). Если не хочется никаких аккаунтов —
сервис можно поднять на своём компьютере и открыть наружу бесплатным туннелем:

```bash
npm run omr:real                       # сервис на http://127.0.0.1:8000
cloudflared tunnel --url http://127.0.0.1:8000   # выдаст публичный https-адрес
```

## 6. Связать приложение с сервисом

1. Откройте приложение на телефоне или компьютере → вкладка **«Сканировать»**.
2. В поле **«Адрес сервиса распознавания»** впишите адрес Space: `имя-fluteband-omr.hf.space`
   (схему можно не писать — подставится `https://`). Адрес хранится на устройстве.
3. Нажмите **«Проверить»** — должно появиться, что сервис отвечает. Затем снимайте ноты камерой.

Чужой сервис трогать не нужно: `dist-space/` — это ваш собственный экземпляр.

## 7. Что проверить после выкладки

- [ ] `https://адрес/index.html` открывается, видны «Библиотека / Сканировать / Минус».
- [ ] Заголовки применились (для Netlify): `curl -I https://адрес/service-worker.js` → в ответе
      `cache-control: no-cache, no-store, must-revalidate`, а у манифеста —
      `content-type: application/manifest+json`.
- [ ] В консоли браузера (DevTools → Application → Service Workers) виден активный service worker
      с областью вашего адреса, а в Cache Storage — кэш `fluteband-shell-…` с 40 файлами.
- [ ] Режим «офлайн» в DevTools: страница перезагружается и работает (это уже проверено на сборке).
- [ ] **Камера** на телефоне открывается по HTTPS (по `http://` браузер камеру не даст).
- [ ] Установка на телефон: «Добавить на главный экран» — приложение открывается без адресной строки.
- [ ] Сервис: `…/health` отвечает, `…/engines` показывает доступный `homr`.
- [ ] Полный круг: фото страницы → минус играет, тональность и темп меняются, экспорт MIDI/WAV работает.

## 8. Что честно сказать про бесплатные тарифы

- **Первый запрос после простоя медленный.** Бесплатные Space спят (при обращении просыпаются, это занимает
  время). Модели движка уже лежат в образе (скачаны на сборке), поэтому ждать их загрузки не нужно.
- **Ядер меньше, чем дома.** Образ собран и запущен локально ровно в условиях бесплатного тарифа (2 ядра,
  4 ГБ) — измерено:

  | Страница | Дома, 16 ядер | На 2 ядрах | Результат |
  |---|---|---|---|
  | демо-страница (разреженная) | ~8–10 с | **23.4 с** | 4 такта, минус «march» — как дома |
  | плотная страница «фортепиано + блокфлейта» | 34.7 с | **130.2 с** | 26 тактов, 229 событий, F-dur, 2/4 |
  | повтор той же страницы | — | **5 мс** | сработал кэш результатов сервиса |

- **Цель 15 секунд** на плотной странице на бесплатном тарифе не гарантируется; быстрый режим
  (только мелодия) — быстрее. Это ограничение площадки, а не приложения.
- **Предел времени на распознавание** в образе — 240 с (переменная `RECOGNIZE_TIMEOUT`). Если площадка
  оборвёт запрос раньше (у платформ бывают свои пределы на длину запроса), ученик увидит ошибку: тогда
  снимайте страницу по половине или поднимите тариф.
- **Данные.** Пьесы и настройки хранятся на устройстве ученика (IndexedDB), на сервер уходит только
  фото страницы — и только на время распознавания.
- **Нигде не нужна карта.** Все площадки выше — с бесплатным тарифом; платные функции не используются.

## 9. Что проверено до выкладки (чтобы не сюрпризов)

- Сборка приложения: 46 файлов, 0.44 МБ, ни одного пути от корня сайта, офлайн-оболочка совпадает с файлами.
- Проверка в подкаталоге (как GitHub Pages): 5 проверок статики + 11 офлайн-проверок, все зелёные —
  приложение открывается с выключенной сетью, service worker управляет страницей, минус строится.
- Проверка для Netlify (приложение в корне сайта): 4 проверки + 11 офлайн-проверок, все зелёные.
  Отдельно проверен и худший случай — **с включёнными «красивыми адресами»** (`npm run check:netlify:pretty`):
  главная страница уходит перенаправлением `301` на `/`, и всё равно вся оболочка (40 адресов) ложится
  в кэш и приложение открывается без сети. Именно из-за этого случая кэширование оболочки переписано:
  раньше один такой адрес отменял установку кэша целиком (`cache.addAll`), и офлайна не было бы вовсе.
- Образ сервиса: собран (1.87 ГБ), контейнер поднимается healthy, работает не от root, `/engines`
  показывает доступный `homr`, распознавание отдаёт тот же нотный текст, что и домашний прогон
  (одна нота из 229 отличается — в контейнере движок использует модели под процессор, а дома стоят fp16).
- Четыре ошибки, видимые только при настоящем запуске контейнера, найдены и исправлены: проверка установки
  движка, системные библиотеки для OpenCV, права на каталог моделей и понятный ответ вместо
  «Internal Server Error» при нехватке времени.
