# Замер распознавания нот (стенд FluteBand AI)

Отчёт создаётся автоматически командой `node tools/omr-bench.mjs` — цифры не вписываются руками.

**Движок:** `homr` · **пьес:** 6 · **провалов:** 0

## Как измерено

1. Эталонный MusicXML (мы знаем каждую ноту) гравируется в SVG (verovio) — это «печатный» оригинал.
2. SVG растеризуется в PNG (Chrome) — получается страница, как из сборника.
3. Страница распознаётся движком OMR.
4. Результат сравнивается с эталоном: нота считается найденной, если совпали такт, высота и позиция в такте (допуск 0.3 доли).
5. Из распознанной пьесы строится минус — проверяется, что тракт работает до конца.

## Выводы для приложения

- Ноты: 125 из 147 найдены верно; пьес без единой ошибки — 2 из 6.
- Длительности нот верны у 79% найденных нот: от них зависит, чем заполнен такт в минусе.
- Тональность 100%, размер 83%, число тактов 33% — остальное требуют проверки учеником (в приложении такие такты помечаются).
- Скорость: в среднем 8623 мс на страницу (CPU, без GPU).
- Аккордовые обозначения движок не читает вовсе: гармонию строит наш модуль `harmony.js` по распознанным нотам, поэтому минус получается даже из «голой» мелодии.
- В MusicXML обязателен `<clef>`: без него движок угадывает ключ и сдвигает все ноты по высоте (проверено: сдвиг на 10-11 полутонов).
- Программы распознавания не пишут `<mode>`: лад нужно определять по нотам (модуль `inferKey`), иначе минор превращается в параллельный мажор.
- Типовые ошибки движка на учебных страницах: лишний такт на переносе строки, путаница 6/8 и 3/8, пунктирные длительности в конце пьесы.
