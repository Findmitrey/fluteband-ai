# FluteBand AI

**Умный аккомпаниатор и транспонировщик для учеников.** Ученик наводит камеру телефона на бумажные
ноты из сборника → приложение распознаёт ноты → мгновенно строит фортепианный «минус» (бас + аккорды
в ритме и темпе) → можно менять темп, зацикливать такт, транспонировать под свой инструмент и скачать
MIDI или WAV. Задача — избавить преподавателя от необходимости постоянно подыгрывать на фортепиано.

Всё построено на **бесплатных инструментах и открытом коде**: чистый JavaScript (PWA), Web Audio API,
Python/FastAPI для сервиса распознавания, открытый OMR-движок homr, свободные SoundFont-банки,
verovio и Chrome для стенда точности.

Честные ограничения: **рукописные ноты не распознаются**; точность измерена на синтетических «печатных»
страницах и на их имитации фото (реальные сканы и фото сборников — следующий замер); выравнивание наклона
работает, но после него по краям страницы остаётся тёмная кромка (на распознавание не влияет);
типовые ошибки движка — лишний такт на переносе строки, путаница 6/8 и 3/8, пунктирные
длительности в конце пьесы (для них есть кнопки-исправления); MP3-экспорт — позже (сейчас WAV и MIDI);
качество тембра рояля измерено числом (обертоны, пик, длительность), но окончательная оценка — на слух:
два готовых файла для сравнения лежат в `artifacts/` (`npm run render:wav`).
Подробности и цифры — в `docs/omr-benchmark.md`, `docs/omr-prep.md`, `docs/omr-photo.md` и `docs/04-status.md`.

## Быстрый старт

```bash
# 1. Сервис распознавания (заглушка, без установок, только Python)
python server/standalone.py                     # http://127.0.0.1:8000

# 2. Приложение (dev-сервер без зависимостей)
node tools/serve.mjs                            # http://localhost:3030 (порт меняется --port=)
```

Откройте http://localhost:3030 → «Библиотека» → «Ода к радости» → «Минус» → «Играть».
Распознавание: вкладка «Сканировать» → снять страницу камерой, **загрузить файл** (фото нот или готовый
`.musicxml` — он разберётся сразу, без сервера) или нажать **«Пример страницы»**, чтобы прогнать настоящее
распознавание без камеры. Файл можно просто перетащить в область кадра.
Снимок перед отправкой обрабатывается на устройстве (выравнивание наклона и света, поиск листа, контраст,
обрезка полей), а после распознавания на экране «Минус» появляется блок **«Проверка распознавания»**
с кнопками-исправлениями.
Dev-сервер проксирует `/api/*` на OMR-сервис; адрес задаётся переменной `OMR_URL`.

**Сборник целиком.** Страницы снимаются по одной: на экране «Сканировать» есть галочка «приклеить страницу
к текущей пьесе» (для пьесы из снимка она включается сама), поэтому вторая и следующие страницы продолжают
ту же пьесу, а не создают новую. Границы страниц сохраняются. В библиотеке пьесы ищутся по названию, автору
и тегам («класс 2», «домашка», «концерт»), у снятых страниц видна обложка, а любую пьесу можно выгрузить
в MusicXML и открыть в MuseScore.

### Как открыть на телефоне

Dev-сервер печатает LAN-адрес (`http://192.168.x.x:3030`). Учтите: **камера работает только в
защищённом контексте** (localhost или HTTPS). Варианты без оплаты:

1. тестировать интерфейс и звук по LAN-адресу (камера будет недоступна, фото — через «Выбрать из галереи»);
2. положить сертификаты в `tools/certs/` (`key.pem`, `cert.pem`) и запустить `node tools/serve.mjs --https`;
3. поднять бесплатный туннель (например, cloudflared) и открыть HTTPS-ссылку на телефоне.

Установка как приложение: в браузере телефона «Добавить на главный экран» (PWA-манифест и офлайн-оболочка уже есть).

## Выложить в интернет (бесплатно)

Приложение — статика, сервис распознавания — небольшое Python-приложение; у каждого своя бесплатная площадка.

```bash
npm run build:static        # → dist/               (46 файлов, 0.45 МБ) для Netlify, Cloudflare Pages или GitHub Pages
npm run check:static        # проверка как на хостинге: подкаталог, service worker, офлайн без сети
npm run check:netlify       # то же для корня сайта (Netlify, Cloudflare Pages)
npm run pack:space:gradio   # → dist-space-gradio/  сервис для бесплатного Gradio-пространства Hugging Face
npm run pack:space          # → dist-space/         тот же сервис как Docker-образ (платный план или иной хостинг)
```

- Сборка приложения не пропустит путь от корня сайта и расхождение с офлайн-оболочкой; имя кэша оболочки
  считается от содержимого пакета, поэтому после обновления ученик не остаётся на старой версии.
- Проверка `npm run check:static` поднимает пакет **в подкаталоге** (`/fluteband/`), то есть ровно так, как
  его отдаёт GitHub Pages, и прогоняет офлайн-проверку на этот адрес: приложение открывается с выключенной сетью.
  `npm run check:netlify` проверяет корень сайта, `npm run check:netlify:pretty` — ещё и худший случай
  Netlify: главная страница отдаётся перенаправлением, но офлайн-кэш всё равно собирается целиком.
- **Сервис выкладывается бесплатно как Gradio-пространство**: Docker-пространства у Hugging Face стали
  платными, а Gradio остались бесплатными. Внутрь Gradio-страницы монтируется наш FastAPI, поэтому
  `/health`, `/engines` и `/recognize` — те же, что у Docker-варианта. Три модели движка (150 МБ) лежат
  в репозитории пространства через git-lfs: диск там непостоянный, а скачивание моделей во время запроса
  ломало распознавание, если рядом шёл второй запрос. Набор моделей соответствует **закреплённой версии**
  движка (`homr==0.6.2`: в базовом образе пространства Python 3.10, а ему нужны модели 331, не 396), и при
  старте пространство сверяет набор с ожиданиями движка. Проверено запуском сервиса с выключенной сетью —
  скачиваний нет. Страница Gradio монтируется с `ssr_mode=False`: серверный рендеринг, который включает
  Hugging Face, поднимает Node-сервер, а тот занимает порт 7860, нужный самому сервису. Пространство
  работает на процессорном железе (**CPU basic**): сервис считает на процессоре, а среда ZeroGPU, куда
  бесплатные Gradio-пространства попадают по умолчанию, не запускает пространство без функции с
  `@spaces.GPU` среди обработчиков страницы. В коде есть подстраховка (помечена вкладка «Состояние
  сервиса», само распознавание — нет) и защищённый импорт `spaces`, поэтому работает и то, и то железо.
- Docker-вариант (`npm run pack:space`) сохранён: он ставит движок `homr`, скачивает его модели на сборке
  (`homr --init`) и добавляет системные библиотеки для OpenCV — без них распознавание в контейнере падало.
  Пригодится с платным планом Hugging Face, на Render или Fly.io.

Пошаговая инструкция (что нажимать, что проверить после выкладки) — `docs/05-publikaciya.md`.
Самая короткая дорога для приложения: открыть <https://app.netlify.com/drop> и перетащить туда содержимое
`dist/` (в репозитории уже лежит `netlify.toml`: сборка `npm run build:static`, папка публикации `dist`,
«красивые адреса» выключены, service worker отдаётся без кэша); для сервиса — создать пространство с
**SDK: Gradio** и загрузить в него `dist-space-gradio/`.

## Боевое распознавание нот (бесплатно)

```bash
# зависимости проекта (fastapi, uvicorn, python-multipart, homr, verovio) кладём в server/deps
pip install --target server/deps -r server/requirements.txt
pip install --target server/deps homr verovio     # homr — движок распознавания, verovio — гравировка для стенда

# запуск боевого сервиса (нужен PYTHONPATH=server/deps)
npm run omr:real                                  # http://127.0.0.1:8000
node tools/omr-check.mjs http://127.0.0.1:8000 app/demo/ode-page.png   # проверить на демо-странице
```

Модели homr (~82 МБ) скачиваются при первом распознавании в `.omr-work/cache`.
Движок `oemer` устанавливается, но с `onnxruntime` 1.30 падает на отрицательных `pads` в ConvTranspose —
поэтому основной движок `homr`; `audiveris` требует Java. Выбор движка виден в `GET /engines`.

### Стенд точности

```bash
npm run demo:page     # демо-страница нот для приложения (app/demo/ode-page.png)
npm run bench:pages   # 6 эталонных пьес уровня 1-3 класса ДМШ
npm run bench         # страница → распознавание → сравнение → минус; отчёт docs/omr-benchmark.md
npm run bench:prep    # влияние подготовки снимка (контраст, обрезка, увеличение, бинаризация); отчёт docs/omr-prep.md
npm run bench:photo   # имитация фото сборника (наклон, стол, тень): что даёт выравнивание; отчёт docs/omr-photo.md
npm run bench:real    # настоящие ноты: библиотечные сканы и файлы пользователя; отчёт docs/omr-real.md
npm run accuracy server/fixtures/bench/01-ode-to-joy.musicxml распознанное.musicxml
```

Фотографии для стенда делает `tools/photo-sim.mjs` (стол с текстурой, поворот и перспективное сжатие листа,
неравномерный свет, размытие, шум). Посмотреть глазами, что подготовка делает со снимком:

```bash
node tools/photo-compare.mjs --piece=06-six-eight --preset=hard   # три картинки в artifacts/
node tools/vision-probe.mjs artifacts/photo-3-deskew.png "Страница ровная? Строки горизонтальные?" --model=qwen3.8-flash
```

Контейнер и бесплатный облачный тариф (Hugging Face Spaces и аналоги) — см. `server/README.md`.

## Тесты и самоконтроль

```bash
# юнит-тесты ядра (ноты, аккорды, гармония, транспонирование, MIDI/WAV, MusicXML, загрузка файлов, ручной ввод)
npm test

# разобрать MusicXML по партиям, станам и голосам (видно, где мелодия, а где фортепиано)
node tools/inspect-musicxml.mjs ноты.musicxml

# проверка OMR-сервиса (HTTP → MusicXML → модель → минус)
node tools/omr-check.mjs http://127.0.0.1:3030/api

# браузерный самоконтроль (нужен установленный Chrome; запускает headless-браузер по CDP)
npm run selfcheck

# проверка офлайн-работы: приложение открывается без сети, пьеса и звук на месте
npm run check:offline

# два WAV-файла одного и того же минуса для сравнения на слух (рояль и встроенный синтез)
npm run render:wav
```

> В этой рабочей среде `npm test` может быть недоступен (npm запускает свой shell, который блокируется
> песочницей) — используйте команды `node` выше. В обычной системе `npm test` и `npm run serve` работают.

Диагностические страницы в браузере: `/diagnostics.html` (полный самоконтроль) и
`/diagnostics-audio.html?delay=0` (изолированная проверка офлайн-рендера звука).

## Выкладывание на бесплатный хостинг

Приложение — это статические файлы, сервис распознавания — отдельный небольшой сервер.

```bash
npm run build:static        # 1. Приложение: собрать dist/ и проверить его как на хостинге
npm run check:static
npm run pack:space:gradio   # 2. Сервис: собрать dist-space-gradio/ (бесплатное Gradio-пространство)
npm run pack:space          #    либо dist-space/ (Docker — для платного плана или другого хостинга)
# 3. В приложении откройте «Сканировать» → «Сервис распознавания» и впишите адрес сервиса:
#    https://ваш-сервис.example.com  → кнопка «Проверить связь» покажет, отвечает ли он
```

Площадки (все бесплатные, без карты): приложение — **Netlify** (самое простое: перетащить содержимое
`dist/` на <https://app.netlify.com/drop>), **Cloudflare Pages** (корень сайта) или **GitHub Pages**
(подкаталог `имя.github.io/fluteband/`); сервис — **Hugging Face Spaces** с **SDK: Gradio**
(`dist-space-gradio/`; Docker там требует платного плана, `dist-space/` для него сохранён).
В репозитории лежит `netlify.toml`, поэтому выкладка из репозитория настраивается сама: сборка
`npm run build:static`, папка публикации `dist`. Подробно, по шагам и с чек-листом после выкладки —
`docs/05-publikaciya.md`.

Почему это работает и проверено: у сервиса открыт CORS (`allow_origins=["*"]`), а приложение умеет
обращаться к сервису по внешнему адресу — в самоконтроле есть проверка, где распознавание идёт настоящим
кросс-доменным запросом на другой адрес (локально: приложение на 3030, сервис на 8000). Если адрес не
указан, приложение обращается к своему каталогу (`api/*`): в корне сайта это прежний `/api/*`, а в
подкаталоге — `…/fluteband/api/*`, то есть в любом случае не в чужой корень.

Важно про HTTPS: камера в браузере доступна только в защищённом контексте, поэтому на телефоне приложение
открывается либо по HTTPS-адресу хостинга (обе площадки дают HTTPS), либо локально (localhost).

## Стек и почему так

- **PWA без фреймворка** (решение пользователя, вопрос 13): ноль сборки, мгновенные обновления,
  один код на Android/iOS/десктоп, бесплатный статический хостинг.
- **Звук синтезируется из нот** (Web Audio), поэтому темп и транспонирование **не меняют высоту тона** —
  это принципиальное преимущество перед воспроизведением готового аудио.
- **Два источника звука, один тракт.** Простой встроенный синтез работает всегда и без интернета; по желанию
  подключается свободный банк записей рояля — Salamander Grand Piano (CC BY 3.0) или компактный FluidR3_GM (MIT).
  Сэмплы скачиваются один раз, лежат в памяти устройства и дальше поднимаются офлайн. Плеер и экспорт WAV
  используют один и тот же инструмент, поэтому файл звучит так же, как звучало в приложении.
- **Распознавание на сервере**, минус строится на устройстве: изображение уходит только на распознавание,
  аудио никогда не передаётся, библиотека пьес хранится локально. Готовый файл MusicXML вообще не требует
  сервера — он разбирается в браузере.
- Все компоненты бесплатны и с открытым кодом: FastAPI (MIT/BSD), homr и verovio (свободные лицензии),
  Audiveris (AGPL), банки звуков Salamander (CC BY 3.0) и FluidR3_GM (MIT), Node/Python (бесплатные рантаймы).
